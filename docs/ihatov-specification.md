# ihatov 仕様書

> 岩手の文学から、ひとこと。

作成日：2026-09-12

最終更新日：2026-09-28

用途：Codex に RSpec によるテスト駆動開発を依頼するための仕様・辞書編集方針

## 1. この文書の位置づけ

本書は ihatov の確定仕様と辞書編集方針を定めるものであり、実装完了を示すものではない。「候補」「例」「実装上の推奨」と明記した部分を除き、決定事項として扱う。

収録候補の引用・表記・インデント・地名の対応関係は、実際の辞書収録時に採用版と照合する。説明用のダミー本文や仮置きの書誌情報を製品データへ転用しない。

## 2. コンセプト・対象範囲・初版規模

### 2.1 基本方針

Faker と同じような手軽さで、岩手の文学に関する一節・固有名詞をランダムに返す独立した Ruby gem を作る。Faker の拡張にはせず、Faker に依存しない。

| 項目 | 決定内容 |
| --- | --- |
| gem 名 | `ihatov` |
| 名前空間 | `Ihatov` |
| キャッチコピー | 岩手の文学から、ひとこと。 |
| 公開リポジトリ | https://github.com/nard-tech/ihatov |
| 対応 Ruby | 3.4 以上 |
| ライセンス | MIT。原典本文・底本・追加注釈の出典確認とは区別する |
| テスト | RSpec による TDD |

対象は宮沢賢治・石川啄木の作品、『遠野物語』、文学・作家・伝承にゆかりのある実在地名。岩手出身の作家だけに限定しない。`Ihatov::Tono` は作者名ではなく、『遠野物語』の作品世界を表す。

### 2.2 初版の収録件数

初版データセットは **25 作品から 157 件**を収録する。作品・作者・出典の管理データは件数に含めず、同じ項目を別作品から `ref` で参照する場合も重複して数えない。

| 種別 | 賢治 | 啄木 | 遠野物語 | 合計 |
| --- | ---: | ---: | ---: | ---: |
| 詩 | 21 | 0 | 0 | 21 |
| 短歌 | 1 | 28 | 0 | 29 |
| 俳句 | 2 | 0 | 0 | 2 |
| 散文 | 14 | 0 | 12 | 26 |
| 擬音語・擬態語 | 9 | 0 | 0 | 9 |
| 地名 | 16 | 6 | 30 | 52 |
| 登場者 | 10 | 0 | 8 | 18 |
| **合計** | **73** | **34** | **50** | **157** |

同じ地名・登場者が複数作品に登場しても一件と数える。擬音語単体と、それを含む文章の抜粋は別項目として数える。収録内容は第 12 章に記録する。

### 2.3 他言語版

JavaScript・Python などへ展開する際は、Ruby 版の辞書とインターフェースを基準にする。収録内容・分類・出典、API の構成・引数・戻り値の意味、抽選・絞り込みの挙動を原則として合わせる。言語仕様上そのまま再現できない部分は移植時に個別に検討する。

## 3. 公開 API と返却オブジェクト

### 3.1 String 継承と凍結

文章・固有名詞・作品を返す API は、メタデータを持つ `String` 派生オブジェクトを返す。Ihatov 固有のメソッドは派生クラスに定義する。返却オブジェクトは凍結する。ActiveSupport の利用方針は第 8 章に従う。

```ruby
place = Ihatov::Kenji.place
# 選ばれた値の例："カルボナード火山島"

place.works           # 関連作品の配列
place.work            # works.first
place.work.title      # "グスコーブドリの伝記"
place.work.author.name # "宮沢 賢治"
place.sources         # 出典の配列
place.source_url      # 先頭の出典の URL
```

文章には `text`、地名・登場者には `name`、作品には `title` という自然な取得名を用いる。同じ文字列を重複して管理する必要はない。作者名は第 6 章の姓名属性から生成する。

出典は取得済みオブジェクトから参照する。

### 3.2 ランダム取得

```ruby
Ihatov.quote
Ihatov::Quote.sample

Ihatov::Kenji.quote
Ihatov::Kenji::Quote.sample
Ihatov::Takuboku.quote
Ihatov::Takuboku::Quote.sample
Ihatov::Tono.quote
Ihatov::Tono::Quote.sample

Ihatov.place
Ihatov::Place.sample
Ihatov::Kenji.place
Ihatov::Kenji::Place.sample

Ihatov.work
Ihatov::Work.sample
Ihatov::Kenji.work
Ihatov::Kenji::Work.sample

Ihatov::Kenji.onomatopoeia
Ihatov::Kenji::Onomatopoeia.sample
# 選ばれた値の例："どっどど どどうど どどうど どどう"
```

同じ対象を取得する簡便メソッドとクラス側の `sample` は、条件・抽選処理を共有する。それぞれを別々に呼べば、それぞれ抽選する。

文章は次の 3 通りの取得方法を提供する。

| 種別 | 簡便メソッド | Quote 側 | 種別クラス側 |
| --- | --- | --- | --- |
| 詩 | `Ihatov.poem` | `Ihatov::Quote.poem` | `Ihatov::Quote::Poem.sample` |
| 短歌 | `Ihatov.tanka` | `Ihatov::Quote.tanka` | `Ihatov::Quote::Tanka.sample` |
| 俳句 | `Ihatov.haiku` | `Ihatov::Quote.haiku` | `Ihatov::Quote::Haiku.sample` |
| 散文 | `Ihatov.passage` | `Ihatov::Quote.passage` | `Ihatov::Quote::Passage.sample` |

著者・作品世界別の取得も同じ構成にする。例：`Ihatov::Kenji.poem`、`Ihatov::Kenji::Quote.poem`、`Ihatov::Kenji::Quote::Poem.sample`。詩・短歌・散文は各名前空間で対応し、俳句は全体・賢治・啄木で取得する。名前空間に対応する項目がなければ、単一取得の空集合ルールに従う。

登場者の取得には `person`・`character`・`creature` を用いる。分類と継承は第 4 章による。

### 3.3 一覧・絞り込み・完全一致検索

```ruby
Ihatov::Kenji::Work.find("銀河鉄道の夜")
Ihatov::Kenji::Work.all
Ihatov::Kenji::Work.where(author: "宮沢 賢治")
Ihatov::Place.where(real: true)
Ihatov::Quote.where(work: "銀河鉄道の夜")
Ihatov::Kenji::Quote::Poem.where(indent: true)
```

- `all`・`where` は凍結済みの通常の `Array` を返す。
- 該当項目がなければ `[]`。検索条件の有無によらず、一覧取得は空集合をエラーにしない。
- `find` は登録された名前・作品名への**完全一致**。不一致は `Ihatov::NotFoundError`。部分一致・曖昧検索を行わない。
- **`Quote.find` は設けない。** 固定した作品などを取得する場合は `Work.find` などを使用する。
- 複数条件は AND。著者別名前空間の範囲を、条件指定によって広げない。
- 一覧と関連作品の順序は第 6 章の年代順ルールに従う。

| 条件 | 値・意味 |
| --- | --- |
| `author:` | 作者オブジェクト、または登録された作者名 |
| `work:` | 作品オブジェクト、または登録された作品名 |
| `real:` | 地名の実在性。`true` / `false` |
| `indent:` | 詩の字下げによる絞り込みと整形。省略時は全詩、`true` は字下げあり・1 段 2 スペース、`false` は字下げなし。文字列は字下げありに絞り、その文字列を 1 段分として整形する |
| `exclude_content_warnings:` | 注意情報がある項目を除外するか。省略時は `false` |

対象種別に適用される条件は `where`・`sample`・簡便メソッドで共通にする。`indent:` の詳細は第 5.3 節に従う。

### 3.4 例外

| 状況 | 挙動 |
| --- | --- |
| 不正な引数 | `ArgumentError` |
| ランダムな単一取得で候補なし | `Ihatov::NotFoundError` |
| 完全一致の `find` で一致なし | `Ihatov::NotFoundError` |
| `all` / `where` で候補なし | 凍結済みの空配列 |

### 3.5 乱数と抽選確率

```ruby
Ihatov.seed = 1234
Ihatov.quote
Ihatov::Kenji::Place.sample

rng = Random.new(5678)
Ihatov.quote(random: rng)
Ihatov::Kenji::Place.sample(random: rng)
```

- `seed=` は gem 全体で共有する乱数生成器を初期化し直す。全名前空間で共有する。
- seed を設定せずに利用できる。
- 明示的な `random:` がある場合は渡された生成器を使い、gem 共通の乱数生成器を消費しない。
- Ruby 全体の乱数状態を `srand` などで変更しない。
- 作者を限定する場合もしない場合も、条件に一致する**各項目を均等に抽選**する。作者ごとの重み付けは行わない。
- 同じ gem バージョン・Ruby バージョン、同じ seed・条件・呼び出し順序で同じ結果を保証する。
- gem または Ruby のバージョンをまたいだ結果の一致は保証しない。共有した生成器を外部で消費する場合、その順序も再現条件に含む。
- 固定の対象が必要なら `Ihatov::Kenji::Work.find("銀河鉄道の夜")` などを使う。本文の完全固定が必要なテストは fixture を使用する。

## 4. 登場者・地名の扱い

### 4.1 Being と 3 分類

共通の親クラスは **`Ihatov::Being < String`**。`Person`・`Character`・`Creature` は `Being` を継承する。「物語に登場する存在」として、人格を持つ信号機・石などの無生物も含める。

| クラス | 区分 | 所属が決まった登場者 |
| --- | --- | --- |
| `Person` | 人間、または基本的に人間の姿で登場する存在。超自然的でもよい | ジョバンニ、カムパネルラ、グスコーブドリ、ネリ、ゴーシュ、高田三郎、座敷童子 |
| `Character` | 動植物・物などをもとにした、人間以外の登場者 | フランドン農学校の豚、山猫、紺三郎、シグナル、シグナレス、ベゴ石 |
| `Creature` | 妖怪・異形・正体不明の存在 | 河童、クラムボン、猿の経立 |

会話や感情の有無だけでは `Creature` にしない。各項目の主分類は一つとし、YAML の `kind` で変更できるようにする。名前などから自動判定しない。`Character` はこの gem では限定的な分類名で、登場者全体は `Being` が表す。

### 4.2 地名と座標

- 地名を定義するときは **`real: true` または `real: false` が必須**。
- 実在性と座標の有無を分ける。`ref:` 側では定義元の `real` を利用する。
- 座標は WGS 84・十進度。Ruby では `{ latitude: Float, longitude: Float }` の凍結済みハッシュ。
- `real: false` なら座標なし（`nil`）。`real: true` でも未登録なら `nil`。
- 山は山頂、地域・川などは代表点を採用する。範囲や線形までは扱わない。
- `Place` には `content_warnings` を設けない。
- 種山ヶ原は実在地名として扱う。座標は典拠を確認して登録する。

## 5. 抜粋・表記・字下げ

### 5.1 抜粋範囲

| 種別 | 収録単位 |
| --- | --- |
| 詩 | 代表的な、まとまりのある一節 |
| 短歌 | 一首全体 |
| 俳句 | 一句全体 |
| 散文 | 最低 3 行程度を目安に、意味のまとまりがある範囲 |
| 擬音語・擬態語 | 対象となる一節 |

散文の行数は選定時の目安。行数を増やすための改行は挿入せず、原文の改行を保持する。散文は童話・説話などの文章を指し、長さではなく文学形式によって分類する。

詩には字下げのある項目を複数含め、長さ・改行の異なる本文を収録する。

### 5.2 表記と出力

- プレーンテキストで返し、HTML 出力は設けない。
- 原文の改行・空行を保持する。末尾改行は付けない。必要なら利用者が追加する。
- 散文の段落頭の字下げは除去する。詩の段階的な字下げは保持する。
- 固有名詞、特殊・歴史的な読みなど、必要なルビだけをカッコ内に表記する。義務教育水準で読みが明らかな一般語には付けない。
- 傍点・注記がある箇所は、あえて採用しない。ただし全文収録を指定した『〔雨ニモマケズ〕』（青空文庫 ID 45630）は例外とし、原文の文字を保持して編集注を除去し、外字を Unicode に置換する。末尾の題目も含め、処理内容は辞書編集ガイドに記録する。
- 採用版の漢字・仮名遣いを無断で現代化しない。
- 擬音語のスペースは半角に統一する。例：`"どっどど どどうど どどうど どどう"`。
- 『注文の多い料理店』新刊案内（青空文庫 ID 43734）のイーハトヴを説明する箇所は、傍点・圏点を省略して本文と必要なルビを保持する例外とし、辞書編集ガイドに処理を記録する。
- 詩の字下げは次節の 2 スペース単位に正規化する。原文にない字下げは創作しない。
- **実装上の推奨**：UTF-8・LF を使用し、本文全体への一律の `strip` や空白圧縮で行頭空白・空行を壊さない。

### 5.3 字下げの選択と整形

```ruby
Ihatov.poem                  # 全詩から抽選。保存された本文を返す
Ihatov.poem(indent: true)    # 字下げありから抽選。1 段を半角スペース 2 文字に
Ihatov.poem(indent: false)   # 字下げなしから抽選
Ihatov.poem(indent: "\t")    # 字下げありから抽選。1 段をタブ 1 文字に
Ihatov.poem(indent: "  ")    # 字下げありから抽選。1 段を半角スペース 2 文字に
Ihatov.poem(indent: "    ")  # 字下げありから抽選。1 段を半角スペース 4 文字に

poem = Ihatov.poem(indent: true)
poem.with_indent("\t")
poem.with_indent(" " * 2)
poem.with_indent(" " * 4)

Ihatov::Kenji::Quote::Poem.sample(indent: "\t")
Ihatov::Kenji::Quote::Poem.where(indent: true)
```

| `indent:` の指定 | 対象 | 返す字下げ |
| --- | --- | --- |
| 省略 | 全詩 | 保存された本文のまま |
| `true` | 字下げのある詩 | 1 段あたり半角スペース 2 文字 |
| `false` | 字下げのない詩 | 字下げなし |
| 文字列 | 字下げのある詩 | 指定文字列を 1 段分として使用 |

- `indent:` による対象の絞り込みは抽選前に行う。文字列指定の場合、選ばれた詩に `with_indent` でその文字列を指定した場合と同じ整形を行う。
- 著者別 API・`Quote.poem`・`Poem.sample`・`Poem.where` でも同じ指定に対応する。`where` は抽選せず、該当する各項目へ同じ整形を適用して凍結済みの配列を返す。
- YAML 本文では**字下げ 1 段あたり半角スペース 2 文字**。YAML 構造上のインデントは数えない。
- `indent:` の省略時および `true` の場合、字下げは保存された 2 スペース単位とする。
- 文字列指定による整形と `with_indent` は、行頭の字下げを指定文字列で段数に応じて置換する。複数段の字下げ、本文中の空白・改行を保持する。
- 整形結果は出典情報を保持した凍結済みオブジェクト。`with_indent` は元のオブジェクトを変更せず、新しいオブジェクトを返す。再抽選しない。

## 6. 辞書構造・ID・出典

### 6.1 保存とファイル配置

編集原本は YAML。gem にも YAML を同梱し、そのまま読み込む。実行時に外部サイトから本文を取得しない。

| ファイル | 内容 |
| --- | --- |
| `data/authors.yml` | 作者の定義 |
| `data/works/miyazawa-kenji.yml` | 賢治の作品・採用版と各作品の全収録項目 |
| `data/works/ishikawa-takuboku.yml` | 啄木の作品・採用版と各作品の全収録項目 |
| `data/works/yanagita-kunio.yml` | 柳田國男の作品・採用版と『遠野物語』の収録項目 |

地名・登場者・擬音語・詩・短歌・俳句・散文は、各作品の下へ収録する。親の作品との関連を読み込み時に組み立て、各項目に `work_id` を重複記載しない。

### 6.2 作者

作者の定義は [`data/authors.yml`](../data/authors.yml) を参照する。

作者 ID は姓→名のフルネームをハイフンで連結する。`name` は YAML に保存せず、半角スペースで姓名を連結するメソッドとする。

```ruby
author.family_name # => "宮沢"
author.given_name  # => "賢治"
author.name        # => "宮沢 賢治"
```

### 6.3 各作品の収録配列

| キー | 内容 | `kind` |
| --- | --- | --- |
| `quotes` | 詩・短歌・俳句・散文 | `poem` / `tanka` / `haiku` / `passage` |
| `places` | 地名 | 不要 |
| `beings` | 登場者 | `person` / `character` / `creature` |
| `onomatopoeias` | 擬音語・擬態語 | 不要 |

文章・擬音語は `text`、地名・登場者は `name`、作品は `title` を保存する。

### 6.4 ID の命名と一意性

- 小文字英数字をハイフンでつなぎ、手動で定義する。
- 公開後は、名称の表記や分類が変わっても ID を維持する。
- 衝突する場合だけ、作者名・作品名などを付け足す。
- ローマ字表記の厳密な統一までは求めない。

| 種別 | 一意性の範囲 |
| --- | --- |
| 作者 | 辞書全体の作者 |
| 作品 | 全作者を通じた作品全体 |
| 抜粋 | 全作品の `quotes`。4 つの `kind` を通じて一意 |
| 地名 | 全作品の `places` |
| 登場者 | 全作品の `beings`。3 つの `kind` を通じて一意 |
| 擬音語 | 全作品の `onomatopoeias` |

異なる種別では同じ ID を使える。`ref:` は同じ種別の ID を参照する。読み込み処理はファイルの順に依存せず参照を解決できるようにする。

### 6.5 採用版と省略ルール

| 属性・配列 | 必須性・省略時の扱い |
| --- | --- |
| 作者の `id` / `family_name` / `given_name` | 作者定義に記載 |
| 各定義の `id` と `title` / `name` / `text` | 対象に応じて記載。`ref` は定義元を利用 |
| `quotes` / `beings` の `kind` | 定義に記載。`ref` は定義元を利用 |
| `edition.aozora_id` | 青空文庫では正の整数。その他の確認済み出典では省略し `nil` |
| `edition.url` | **必須**。図書カードまたは採用した掲載元の URL を記録 |
| `edition.bibliography` | 必須。底本情報の文字列 |
| 各項目・参照の `location` | 任意。省略時は `nil` |
| 各項目・参照の `source_url` | 任意。省略時の公開値は、その出典の作品の `edition.url` |
| `content_warnings` | 任意。省略時は `[]`。地名には設けない |
| 4 つの収録配列 | 空なら省略可。省略時は `[]` |
| 年代 | 未登録なら省略または `null`。読み込み時は `nil` |
| `coordinates` | 未登録なら省略または `null`。読み込み時は `nil` |
| 地名定義の `real` | 必須。座標とは独立した boolean |

### 6.6 Edition・Source と関連作品

| クラス・属性 | 内容 |
| --- | --- |
| `Ihatov::Edition` | 採用版の専用クラス。`aozora_id`・`url`・`bibliography` を持ち、凍結する |
| `Work#edition` | その作品の `Edition` |
| `Ihatov::Source` | 一つの作品との出典関係を表す専用クラス。凍結する |
| `Source#work` | 出典作品 |
| `Source#location` | 作品内の位置を示す文字列、または `nil` |
| `Source#source_url` | 該当箇所の URL。指定がなければ `work.edition.url` |
| 項目の `sources` | 出典を年代順に並べた配列 |
| 項目の `works` | 関連作品を重複なし・年代順で保持する属性 |
| 項目の `work` | `works.first` を返すメソッド |
| 項目の `location` / `source_url` | 先頭の出典から取得するメソッド |

`sources` の先頭の作品と `work` が一致するように並べる。`location` は章・話数などの説明文字列であり、機械的な解析を前提にしない。アンカーが確認できた場合、`source_url` にアンカー付き本文 URL を記録する。なければ本文ページ URL も指定できる。

```ruby
quote.work.edition.aozora_id
quote.work.edition.url
quote.work.edition.bibliography
quote.location
quote.source_url

place.sources.first.work
place.sources.first.location
place.sources.first.source_url
```

### 6.7 共有対象と ref

同じ地名・登場者を一か所で定義し、別作品では `ref:` で参照する。読み込み時に一つの対象にまとめ、関連作品と出典を集約する。

`location`・`source_url` は対象そのものではなく、**各作品との関連ごと**に指定できる。定義元の位置情報を別作品の参照へ流用しない。参照先が見つからない辞書は検証で検出する。

次の例は構造説明用のダミーで、採用版などは省略している。

```yaml
works:
  - id: work-a
    title: 作品A
    places:
      - id: shared-place
        name: 共通の地名
        real: true
        location: 第一章
        source_url: https://example.com/work-a.html#chapter-1

  - id: work-b
    title: 作品B
    places:
      - ref: shared-place
        location: 第三章
        source_url: https://example.com/work-b.html#chapter-3
```

### 6.8 年代と辞書内の掲載順

- 発表年を優先し、不明なら刊行年を使う。
- 発表年と刊行年に大きな隔たりがある場合、辞書作成時に個別に検討する。
- 年代が分かる項目は古い順。年代不明（`null` / `nil`）は最後。
- 同年同士・年代不明同士は YAML の定義順を維持する。
- 作者をまたぐ同年順は、`authors.yml` の定義順とする。
- 一覧取得・`works`・`sources` は、この年代順に並べる。
- 作者別 YAML の作品掲載順は、初版の収録内容を示す第 12 章に合わせる。
  - 宮沢賢治は、12.2 の散文作品を発表年順に置き、12.3 の詩、12.4 の短歌「うるはしの」、12.5 の俳句と続ける。散文の年代不明作品は年代が分かる作品の後に 12.2 の順で置き、地名だけを収録する作品はその後に 12.7 の順で置く。
  - 石川啄木は、12.4 の『一握の砂』『悲しき玩具』の順とする。歌集の順序を変更する場合は、発表年または刊行年の古い方を先にする。
  - 柳田國男は『遠野物語』一作品とし、作品内の散文を 12.6 の話数順に置く。

### 6.9 採用版・重複の編集方針

- 新字を旧字より優先し、新仮名を旧仮名より優先する。適切な版がなければ旧字・旧仮名でもよい。
- まず代表的な収録箇所を選び、希望する表記の版で確認する。同じ文字遣いの底本が複数ある場合、作品ごとに一つを選び、青空文庫作品 ID を固定する。
- 詩集と収録詩の作品単位は、採用する青空文庫データの構成に合わせる。
- 初版では同一作品の複数の版を混在させない。抜粋に違いがある場合に版を比較する。
- 『遠野物語』は[新字新仮名版・作品 ID 52504](https://www.aozora.gr.jp/cards/001566/card52504.html)を採用する。
- 同じ作品の同じ一節を重複登録せず、一件にまとめる。
- 同じ対象の地名・登場者は一件にまとめ、`ref` と `works` で複数作品に関連付ける。
- 編集した呼称を用いる場合は、本文中の固有名と混同しないよう由来を確認する。

参考：[賢治作品一覧](https://www.aozora.gr.jp/index_pages/person81.html)、[啄木作品一覧](https://www.aozora.gr.jp/index_pages/person153.html)、[柳田作品一覧](https://www.aozora.gr.jp/index_pages/person1566.html)。

### 6.10 統合した YAML 記述例

**以下は構造説明用。本文・底本情報はダミーであり、完成した辞書データではない。** 年代キー `announced_year`・`published_year` は記述例で使用する名称で、最終的な内部属性名は実装時に統一する。

```yaml
# data/works/yanagita-kunio.yml

  - id: tono-monogatari
    title: 遠野物語
    edition:
      aozora_id: 52504
      url: https://www.aozora.gr.jp/cards/001566/card52504.html

        ここに確認した底本の書名・叢書・出版社を記録する
        発行年・版などを記録する

    quotes:
      - id: tono-monogatari-episode-59
        kind: passage
        location: 第59話

      - id: kappa
        kind: creature
        name: 河童

```

字下げを含む詩の本文部分の例（ダミー）：

```yaml
quotes:

        一段下げた行
          二段下げた行
      字下げのない行
```

`|-` は改行を保持し、末尾改行を除く。`|2-` は YAML 構造上の字下げ幅を明示し、本文の先頭から字下げがある場合にも保持できる記法。本文の字下げ 1 段は 2 スペースとする。

## 7. 注意情報と README

### 7.1 歴史的表現への注意

現代では不適切・差別的と受け取られる可能性のある表現について、README とデータ属性に注意を記載する。

- 判定は、OpenAI の利用規約・ポリシーを緩やかな編集上の参考とし、問題になりそうな表現を注意対象にする。
- 収録時に判定する。実行時の OpenAI API 呼び出しや依存は設けない。
- 注意対象であることを、正式な規約違反の判定と同一視しない。
- `content_warnings` は説明文の配列。注意なしなら `[]`。YAML では省略できる。
- 地名にはこの属性を設けない。
- 旧仮名遣いそのものを警告対象と混同しない。作品全体に注意があることだけで全抜粋に同じ警告を付けない。

```ruby
Ihatov.quote(exclude_content_warnings: true)
Ihatov::Quote.where(exclude_content_warnings: true)
```

`true` なら `content_warnings` が空でない項目を除外する。省略時は `false` として、注意情報がある項目も抽選・検索対象に含める。除外後の空集合は第 3 章に従う。

README の注意文案：

> 本 gem に収録する作品には、執筆当時の社会的・歴史的背景を反映した表現が含まれます。その中には、今日では不適切または差別的と受け取られる可能性のある表現もあります。
>
> 本 gem は、ルビ・空白など本仕様に定める整形を除き、典拠の表記に基づいて収録します。収録された表現は、本 gem および開発者の見解や価値判断を示すものではありません。
>
> 注意情報が付いた項目を除外する場合は `exclude_content_warnings: true` を指定してください。利用する文脈と対象者に応じて内容をご確認ください。

## 8. 実装・CI・リリース

### 8.1 対応環境・依存関係

- Ruby 3.4 以上。gemspec は `spec.required_ruby_version = ">= 3.4"`。
- RSpec でテスト駆動開発する。
- **ActiveSupport（`activesupport`）を実行時依存として許可する。** `present?`・`blank?` などを利用でき、必要な拡張だけを読み込む。
- その他の依存は最小限にする。RSpec・RuboCop・YARD は開発用とし、実行時依存に含めない。

### 8.2 実装方針

- メタプログラミングを使わない。公開メソッド・名前空間・種別との対応を明示する。
- `method_missing`、`define_method`、`define_singleton_method`、動的な `const_set`、`eval` 系、`send` / `public_send` による API 振り分けを行わない。`public_send` は基本的に使わない。
- 通常のクラスを基本にする。明示的な値型には `Data.define` を使用してよいが必須ではない。`Struct` は使用しない。
- `Edition`・`Source` は専用クラスとする。`String` 継承が必要な値クラスを `Data.define` で置き換えない。
- 返却値と公開するメタデータは凍結し、配列・ハッシュ内の値から共有辞書を変更できないようにする。
- YAML の値からクラス名を動的に解決せず、明示的な対応付けで読み込む。

内部の Repository・Sampler などの責務分割は、公開仕様を守る範囲で実装時に決める。必要以上に独立クラスを増やさない。

### 8.3 YARD によるドキュメント化

公開クラス・メソッドを中心に、YARD 形式のコメントを付け、API ドキュメントを生成できるようにする。

| 記載内容 | 形式 |
| --- | --- |
| クラス・メソッドの役割 | 説明文 |
| 引数の型・意味・省略時の挙動 | `@param` |
| 戻り値の型・意味 | `@return` |
| 発生する例外と条件 | `@raise` |
| 使用例 | `@example` |

`indent:` のように型によって挙動が変わる引数は、boolean・文字列・省略時の違いを明記する。凍結済みオブジェクトを返すことや、空集合の扱いも説明する。YARD は開発用の依存とする。

### 8.4 GitHub Actions の CI

- 公開リポジトリに GitHub Actions のワークフローを組み込む。
- PR と push を契機に、RuboCop によるコード検査と RSpec によるテストを実行する。
- RSpec は Ruby 3.4 以上の各バージョンをマトリクスで検証する。新しい対象バージョンが出たら更新する。
- RuboCop は開発用の依存として追加する。

### 8.5 リリース

PR とリリースタグで運用する。リリースは最初は手動で行い、後から GitHub Actions で自動化する。

## 9. RSpec・辞書検証

`it` は「〜こと」で終わる日本語の後に英語を併記する。`context` の条件は日本語の「〜とき」に統一し、その後に英語を併記する。共通の対象は `let`、準備は `before` で整理する。

主に以下の契約をテストで確認する。

1. 文字列派生の値として使え、本文・名称と出典にアクセスでき、返却値が凍結されている。
2. 簡便 API とクラス API が同じ範囲・条件を扱い、著者・作品世界の範囲を守る。
3. `find` の完全一致、`ArgumentError`、単一取得の `NotFoundError`、一覧の空配列が仕様どおりである。
4. 同じ gem・Ruby・seed・条件・呼び出し順序で再現できる。個別 `random:` が全体乱数へ影響しない。バージョンをまたぐ固定出力を要求しない。
5. 条件適用後の各項目を均等抽選する。偶然全候補が出揃うことを期待する不安定なテストは避ける。
6. `indent:` の省略・`true`・`false`・文字列指定の対象と整形を確認する。`true` の 1 段 2 スペース、タブ・指定スペース数への変換、`with_indent` の段数保持、出典の引き継ぎ、元の値の不変性を確認する。
7. 原文由来の改行・空行、末尾改行なし、必要なルビの表記、擬音語の半角スペースを確認する。
8. 種別内の ID 重複、未解決の `ref`、必須属性の欠落、不正な `kind` などの辞書誤りを検出する。
9. `ref` で同じ対象がまとまり、作品ごとの `location`・`source_url` が保持される。URL 省略時の参照先も確認する。
10. 一覧取得の年代順、同年の定義順、年代不明が末尾になることと、作者別 YAML が第 12 章の掲載順に沿うことを確認する。
11. YAML 省略値が `[]` / `nil` となること、`real` と座標の有無が独立していることを確認する。
12. 注意情報の省略・除外・既定値 `false` を確認する。
13. ビルドした gem に YAML が含まれ、外部通信なしで利用できることを確認する。

本文の正確さは必須属性や URL の存在だけでは保証できない。収録時の典拠照合を別途行い、検証済みの fixture を用いる。
